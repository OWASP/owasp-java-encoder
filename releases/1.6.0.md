# OWASP Java Encoder 1.6.0

**Release preparation; not yet published.** The latest verified Central release
remains [1.5.1](1.5.1-central-publication.md). This minor release reduces
unnecessary JavaScript letter escaping while preserving recognized HTML-token
protection across trusted fragments. It introduces no new encoder security fix.
Do not treat a successful build or staging validation as publication.

## Highlights and compatibility

[PR #247](https://github.com/OWASP/owasp-java-encoder/pull/247) resolves
[#243](https://github.com/OWASP/owasp-java-encoder/issues/243):

- `forJavaScript` and `forJavaScriptBlock` leave interior script-name letters
  readable. The last input character remains escaped if it is C, I, P, R, S,
  or T in either case. Punctuation and whitespace escapes remain.
- HTML does not remove whitespace inside tag names. Escaping `<` in a complete
  string addresses the HTML tag delimiter concern, but cannot protect fragments
  whose trusted prefix supplies `<`. The retained terminal escape protects that
  supported composition case.
- `EncodedWriter.flush()` safely emits a pending script letter or high surrogate
  in general/block JavaScript modes. Flush before writing directly to its wrapped
  writer; prefer the complete-value Writer facade for a value followed by trusted
  output. Ordinary chunking matches whole-value output. Flushes can add escapes
  while preserving the JavaScript UTF-16 value.

| Input | 1.5.1 general/block output | 1.6.0 general/block output |
| --- | --- | --- |
| `http://google.com` | `h\x74\x74\x70:\/\/google.\x63om` | `http:\/\/google.com` |
| `script` | `\x73\x63\x72\x69\x70\x74` | `scrip\x74` |
| `i` | `\x69` | `\x69` |
| `cat` | `\x63a\x74` | `ca\x74` |

The final-letter rule is conservative, not minimal: `csript` becomes
`csrip\x74` even though it is not a script tag name. Source and attribute-only
modes are unchanged. The guarantee concerns recognized HTML tokens, rather than
every literal `</script` substring; longer names such as `</scripture>` are
harmless to the HTML script tokenizer. Existing context and insertion-boundary
requirements still apply, including empty-input and unsafe-template exclusions.

Encoded bytes, snapshots, signatures and cache keys can change. Low-level
`Encoder.encode` callers must preserve unread input after UNDERFLOW and supply
more input or mark end-of-input, now including a retained ASCII letter.
See the [migration record](../docs/compatibility-decisions.md#javascript-output-refinement-in-160-243).

Java 8 remains the minimum runtime. Public APIs, null handling, JavaScript string
values, runtime dependencies, Maven identities, module/bundle identities and
servlet namespaces are unchanged. Core has no runtime dependencies. Keep core
and adapter versions aligned; do not combine javax and Jakarta adapters on one
classpath or module path.

The [1.5.0 security fixes](1.5.0.md) remain in effect. Applications on older
versions should follow that release's migration guidance and
[security advisory](https://github.com/OWASP/owasp-java-encoder/security/advisories/GHSA-g8p6-7r8f-qrpv).
